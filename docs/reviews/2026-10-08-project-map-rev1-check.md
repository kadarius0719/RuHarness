### coherence — the document as a whole (revision 1 at cc2b752; line numbers from that commit)

**High**
1. **`compile_commands.json` flags are per file; the design treats a configuration as one set of flags for the target.** Step 4 (l.89) takes each file's flags; §3.2 (l.169) says per-file configuration is not expressible; §3.7 (l.322) `Base` carries target-wide flags; `files[].flags_from` (l.192) suggests per-file flags nothing uses. 2. **"One configuration per accepted tool" cannot work with one project-level `config.toml`, one `configuration` in the map, and the run name inside it** (l.145–147, 154–156, 185, 171–172, 223 "per scope"). To accept lz4's tool and its tests under different configurations the person would edit the file and re-map, and the later map would falsely say "configuration changed" for the first tool; `run_name` cannot be one value for several programs; "per scope" was ruled overreach. Fix: `config.toml` holds `[[configuration]] name, builds, flags` (one or more); `map --configuration <name>`; the run name is not part of a configuration — `accept --run-name`, default the entry's stem; a map compares an accepted tool only with a map made under that tool's configuration name; drop "per scope".
3. **"The harness's own ledger folder" is undefined, and the second `map` run hits the shipped-`migration/` refusal** (l.65, 311–317, 304–308, 330, 379): the first run creates `migration/map/`, the second finds `migration/` existing; "before the first map" cannot be tested by `project-map.json` (a download can ship one). Which lock `map` takes is unclear (no ledger before accept, several after). Fix: the harness's own `migration/` is one whose `migration/map/owner.json` it wrote (canonical root + root_hash); one without it, or naming another root, is shipped; a project-level lock `migration/map/.lock` for map/ask/accept. A copied marker is possible: the root check is the minimum; ask the security checker.
